## Why 1.8.0 and not 1.7.2

36 commits since v1.7.1, headlined by a new home screen. That is a minor bump,
not a patch. versionCode 12 follows 11 with no gap.

## The one thing to know about the rollout

**The globe is the default, so every updating user lands on it.** `homeView`
now defaults to `'globe'`, and the settings migration reads so that only an
explicit `'list'` keeps the list — a missing or unrecognised value falls to the
globe. `homeView` has never shipped (it was added after v1.7.1), so no existing
user has a stored value: everyone updating from 1.7.x opens onto the globe.

The choice is sticky in both directions. Anyone who switches to the list in
Settings → Appearance keeps it across restarts and future updates, and new
installs are still offered the choice during onboarding.

**Scale note, which changes the rollout advice.** The install base is the
maintainer and family — not the public. Staged rollout, vitals-watching and
review-reading are all machinery for catching problems among strangers who
will not report them; none of it produces signal at this size. Ship at 100%.

The one thing worth knowing is that WebGL now runs on the home screen for
everyone rather than for volunteers, and GPU behaviour varies by device more
than anything else in the app. On an older or budget handset the globe may be
slow, and a context failure renders as a dark screen rather than a crash. The
remedy is Settings → Appearance → list, which sticks — worth mentioning to
anyone on old hardware rather than watching a dashboard for it.

## Data safety: worth a glance, probably unchanged

The globe home view streams satellite tiles from Esri
(`server.arcgisonline.com/ArcGIS/rest/services/World_Imagery/...`,
`homeGlobe.ts:621`). This is new since 1.7.1 — `three-slippy-map-globe` was not
a dependency then, and the qibla globe used bundled `land-50m` vector data and
fetched nothing over the network.

**What Esri actually receives:** the device's IP address, as any HTTP request
carries, plus the tile coordinates for whatever is on screen. No coordinates,
no identifier and no account are sent. The framing is coarse — `HOME_ALTITUDE`
is 2.5 earth-radii, a whole-globe view, and even the "My location" fly-in stops
at `FOCUS_ALTITUDE` 0.5, which is regional rather than local. Ground view, the
only close-in framing, is commented out.

That is ordinary map-tile behaviour, the same shape as any app using a basemap
SDK, and it is not the "location shared with a third party" that the Data
safety form is asking about. **The expectation is that no change is needed.**
Give the form a look before rolling out, since the network behaviour did change,
but do not expect to rewrite it.

Nothing else on the Console changes: **Content rating** and **Target audience**
are unaffected, and no permission was added or removed.

## Play Console steps

1. **Play Console** → **OnTime** (`com.ontimeapp.prayer`) → **Release** →
   **Production** → **Create new release**.
2. Glance at the Data safety form (see above); no change is expected.
3. Confirm **Play App Signing** is enrolled (App integrity → App signing). If it
   is, the fingerprint above is the *upload* key and Google re-signs with the
   production key — expected, not an error.
4. **Upload** `OnTime-v1.8.0.aab`. Wait for the "versionCode 12" confirmation and
   check no pre-launch errors block the release.
5. **Release name:** `1.8.0 (12)`. Paste the release notes above into *What's new
   in this release* for `en-US`.
6. **Rollout: 100%.** No staging — see the scale note above. A percentage of a
   family-sized install base is a couple of phones and yields no signal, and
   the rollback position (halt, ship versionCode 13) is the same either way.
7. **Save** → **Review release** → **Start rollout to Production**.

## After rollout

- Push the commit and tag: `git push origin main --follow-tags`
- No dashboard-watching needed at this scale. If the globe is slow or dark on a
  family member's older phone, Settings → Appearance → list fixes it and sticks.
- Esri tile fetches are unauthenticated and unmetered by us; if the Console or
  Esri flags volume, the fallback is the bundled `earth-base.jpg`, which already
  renders the globe without any network at all.

## Known follow-ups (none blocking)

- **The moon texture is hotlinked** from `https://threejs.org/examples/textures/
  planets/moon_1024.jpg` (`homeGlobe.ts:67`). It degrades gracefully — the load
  has no error callback and the moon simply stays flat-shaded — but a shipped app
  should not depend on another project's example CDN. Bundle it locally in 1.8.1.
- **Esri World Imagery terms** for unkeyed use in a published app were not
  verified for this release. Attribution is rendered in-app; confirm that is
  sufficient under current ArcGIS terms.
- **The upload keystore password is weak** — see `android/keystore.properties`
  (gitignored; the value is deliberately not repeated here). Under Play App
  Signing this is only the upload key and can be rotated via App integrity
  without affecting installed users. Worth doing, not urgent.
- **Ground view** remains commented out in `HomeGlobeScreen.tsx`; the machinery
  behind it is intact. Decide whether it returns or gets deleted.
- **Dead `glow` layout** in `CountdownTimer.tsx` / `IslamicCountdownTimer.tsx` is
  now unreachable in globe mode and can be removed.

## Rollback

Halt the rollout in the Production release page. Play cannot un-publish a
versionCode, so a fix ships as versionCode 13. The previous production build
stays installed for users who never received 12.
