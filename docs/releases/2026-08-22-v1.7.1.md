## Why 1.7.1 and not 1.7.0

An `OnTime-v1.7.0.aab` (versionCode 10) was built on 2026-08-20 and already
contained the 3D work, but whether it ever reached the Play Console was
unknown. versionCode 11 is safe either way — Play only requires the code to
increase, and gaps are fine (9 was already skipped). Do not attempt to reuse
10.

## Play Console steps

1. **Play Console** → **OnTime** (`com.ontimeapp.prayer`) → **Release** →
   **Production** → **Create new release**.
2. Confirm **Play App Signing** is enrolled (App integrity → App signing). If
   it is, the fingerprint above is the *upload* key and Google re-signs with
   the production key — expected, not an error.
3. **Upload** `OnTime-v1.7.1.aab`. Wait for the "versionCode 11" confirmation
   and check no pre-launch errors block the release.
4. **Release name:** `1.7.1 (11)`. Paste the release notes above into
   *What's new in this release* for `en-US`.
5. Leave **Data safety**, **Content rating**, and **Target audience** as they
   are — nothing in this release changes data handling or permissions.
6. **Staged rollout:** start at **20%**, not 100%. This is the first release
   with WebGL on the home screen; GPU behaviour varies by device far more
   than the rest of the app. Watch Android vitals (ANR rate, crash rate) for
   24–48h, then step to 50% and 100%.
7. **Save** → **Review release** → **Start rollout to Production**.

## After rollout

- Push the commit and tag: `git push origin main --follow-tags`
- Watch **Android vitals → Crashes and ANRs**, filtered to app version 11.
  A WebGL context failure would show as a blank card, not a crash — also
  watch the reviews for "black box" / "blank" reports.
- `docs/3d-backlog.md` holds the deferred follow-ups (fading past prayers,
  the globe-clipping question, day/night terminator).

## Rollback

Halt the rollout in the Production release page. Play cannot un-publish a
versionCode, so a fix ships as versionCode 12. The previous production build
stays installed for users who never received 11.
